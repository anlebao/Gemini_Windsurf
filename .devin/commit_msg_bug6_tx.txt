fix(loyalty): Bug 6 — AddPointsAsync nested transaction error

Root cause: OrderWorkflowService.TransitionStatusAsync begins a DB
transaction, then calls ProcessLoyaltyPointsAsync then AddPointsAsync.
AddPointsAsync called BeginTransactionAsync again but SQLite does not
support nested transactions, so exception thrown, order transition
rolled back, 404 returned to client.

Fix: AddPointsAsync now supports ambient transactions. If a transaction
is already active on the DbContext, it joins it (no explicit
BeginTransaction/Commit/Rollback — the caller owns the transaction
lifecycle). This allows loyalty points to be awarded atomically with
the order status transition.
