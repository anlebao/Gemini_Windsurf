[HOTFIX] Blazor @onclick not processed in UI.Platform class library — add @using Microsoft.AspNetCore.Components.Web

Root cause: UI.Platform class library components (VanAButton, VanAInput,
VanASelect, VanAForm, VanAModal, VanAAlert, DynamicForm, VanAnModal,
VanAnAlert) use @onclick/@onchange/@onsubmit event directives on HTML
elements. Without @using Microsoft.AspNetCore.Components.Web, the Razor
source generator treats @onclick as a LITERAL HTML attribute (with @ in
the name) instead of an event handler directive.

Evidence (generated code BEFORE fix):
  __builder.AddAttribute(5, "@onclick", "HandleClick");  // LITERAL STRING

Evidence (generated code AFTER fix):
  __builder.AddAttribute(5, "onclick",
    EventCallback.Factory.Create<MouseEventArgs>(this, HandleClick));  // EVENT HANDLER

This caused ALL buttons in VanAButton (and other UI.Platform components)
to be non-functional on VPS — @onclick="HandleClick" rendered as a literal
HTML attribute, clicks did nothing.

Pattern fix (not case-by-case):
- Added @using Microsoft.AspNetCore.Components.Web to 9 .razor files in
  UI.Platform that use @on* event directives
- VanAButton.razor + VanAnButton.razor already had the import (or just added)
- VanAnSearchBar.razor already had the import

Also includes previous commit's prerender:false change (43 pages) which
fixes the circuit hydration issue. Both fixes are needed:
  1. prerender:false — circuit renders from scratch (no hydration needed)
  2. @using Components.Web — @onclick processed as event handler (not literal)
